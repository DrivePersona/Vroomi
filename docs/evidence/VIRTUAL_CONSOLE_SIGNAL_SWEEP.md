# Virtual Console 신호 전수 점검 증적

검증일: 2026-11-14  
대상: `Pleos_Connect_v2_1_0` (사용자 10, `internalDebug`, 캐릭터 `ai.meshy.chuuni`)  
방법: Virtual Console REST(`:8088`)로 카탈로그 63개 기능의 값을 하나씩 넣고, 앱 logcat(`차량 입력 → 말하기 요청 → 재생됨`)으로 반응을 판정했다. 절차는 [PLEOS_VIRTUAL_CONSOLE_E2E](../guides/PLEOS_VIRTUAL_CONSOLE_E2E.md)를 따른다.

이 문서는 **에뮬레이터 확인**이다. 실차 확인이 아니고, 소리는 로그로만 확인했다(스피커로 들은 것이 아니다). 캐릭터 몸짓은 확인하지 못했다(아래 한계).

## 방법과 보정
- 주차(P) 상태에서 106단계를 두 번 돌렸다. 각 값은 기준값을 조용히 맞춘 뒤 넣었다.
- 두 번 사이에 결과가 갈린 항목은 기준값 설정 뒤 14초를 기다려 두 번 다시 쟀다. 갈림의 대부분은 이벤트별 쿨다운(도어·창문·조명 등)이었다.
- 기어는 P → D → N → R → P → D로 34초 간격(기어 이벤트 쿨다운 30초 회피)으로 넣었고, D 상태에서 신호를 넣어 주행 중 허용 여부를 봤다.
- 콘솔은 브라우저 하트비트가 없으면 503을 준다. 점검 스크립트가 하트비트를 직접 보냈다.

## 결과 4: 앱에 신호가 오지 않음
- etcs 활성·시나리오, 전원 상태, 계기판 경고등(telltales): 콘솔 상태는 바뀌는 것을 확인했다. 앱이 구독하지 않는 것으로 보인다.
- 유독가스 알림, 비상등, 정지등, 도어등, 에스코트등: 앱 수신 없음. 콘솔 상태 변경은 확인하지 못했다.
- **타이어 공기압: 수신 없음. 앱에 TIRE 이벤트 매핑이 없다(공백).**
- EV 배터리 레벨·용량·충전 설정, 주행 시간, 크루즈 longitudinal·lateral
- 시트 위치·이동 15개, 공조 풍향, 앰비언트 스위치·밝기, 외부등 Auto, 와이퍼 Low·High, 글러브박스

이 중 콘솔 상태 변경까지 확인한 것은 etcs, 전원 상태, telltales뿐이다. 나머지는 콘솔이 값을 내보냈는지 확인하지 못했다.

## 주행(D) 중 허용·차단
| 신호 | 결과 |
| --- | --- |
| 브레이크·방향지시등·크루즈 목표속도·주행 가능 거리·조향 400°·외부등 | 반응 + 음성(주행 중 허용) |
| 공조 온도·도어 잠금·창문·실내등 | 주행 중 차단(로그 `주행 중 허용=false`). 설계대로 |
| 공조 전원 | 데이터만 |

기어 이벤트와 주행 상태: D·R에서 주행=true, P에서 false. N은 이벤트가 없다.

## 한계
- 에뮬레이터는 3D를 그리지 않고 2D 프리뷰만 보인다([PLEOS_PLATFORM_FINDINGS](../platform/PLEOS_PLATFORM_FINDINGS.md)). 캐릭터가 어떻게 움직였는지는 화면이 아니라 로그로만 봤다.
- 장착 가능한 캐릭터는 모두 idle 몸짓만 있어, 반응 중 몸짓(`몸짓 시작`)은 한 번도 나오지 않았다(`몸짓 없음`).
- 일부 반응은 캐릭터 클립이 없어 대체 TTS로 재생된다(chuuni의 TOUCH·DOOR 등).
- WARNING은 시트벨트 좌/우에서만 나오는데 콘솔이 그 값을 줄 수 없어 확인하지 못했다. MODE는 콘솔에 제어 항목이 없다.
- 점검 스크립트의 첫 실행에서 일부 값이 잘못 들어가(방향지시등 파라미터·크루즈 값·타이어 영역) 400이 났고, 같은 결과를 재측정으로 바로잡았다. 표의 판정은 바로잡은 값 기준이다.

## 후속
- 기어 N 반응 여부 결정(의도인지 확인)
- 주행 중 크루즈 `full_autonomous` 이벤트 원인 확인
- TIRE 이벤트 매핑 추가
- 반응 중 캐릭터 몸짓은 3D가 보이는 기기에서 확인
