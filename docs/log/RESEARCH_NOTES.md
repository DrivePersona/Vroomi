# 조사 기록

**기준일:** 2026-11-12 · 웹·GitHub 조사 결과다. 별도 표기가 없으면 **코드를 내려받아 실행하지 않았고**, 라이선스는 저장소·모델 카드에서 읽은 것이므로 **배포 전에 원문 재확인이 필요하다.** 결론은 조사자 판단이다.

## 1. 음성 팩 방식 (캐릭터 목소리를 바꿔 끼우기)

| 안 | 내용 | 평가 |
| --- | --- | --- |
| A | 플랫폼 화자 전환(`setSpeakerType`) | 값 목록을 접근 가능한 문서에서 못 찾음 |
| **B** | **녹음 클립 팩** (캐릭터 O, 자유 문장 X) | **채택.** 가장 단순하고 지연이 없다 |
| C | 자체 온디바이스 모델 팩 (자유 문장 O) | 보류. 아래 게이트 통과 필요 |
| D | 서버 합성(Pleos HYBRID/SERVER 또는 자체 서버) | v1 범위 밖 |

C안 PoC 게이트: ① 모델·데이터·전처리 의존물의 라이선스 원문 ② 한국어 청취 품질 ③ 대표 기기에서 문장당 합성 시간 ④ 팩 크기(Pleos 용량 제한). 후보로 Supertonic 3(ONNX, 한국어 포함), MeloTTS Korean(MIT, 공식 ONNX 내보내기는 못 찾음)을 봤고 어느 쪽도 **우리 캐릭터 음색을 새로 만들 수 있는지는 확인하지 못했다.** 한국어 단일 화자 데이터셋 KSS는 비상업(CC BY-NC-SA)이라 상업 모델 학습에 못 쓴다. 성우 계약에는 합성 모델 학습·상업 이용·재배포 범위를 넣어야 한다.

클립 팩 형식(schema 1)은 manifest + WAV(PCM16, 모노, 16~48kHz) + 파일별 SHA-256·크기, 클립 4초·1MB, 팩 5MB, `provenance`(캐릭터 original, 음성 출처, 동의, 라이선스, 상업 이용) 필수다. 중립 음성 이벤트(경고)는 팩을 쓰지 않는다.

## 2. 음성 → 전신·3D 아바타 동작 생성

결론: **같은 문제 영역이지만 바로 쓸 부품은 없다.**

- **라이선스:** 대표 연구 저장소(EMAGE 계열)는 LICENSE 파일이 없고 모델 카드는 apache-2.0 표기·본문 비어 있음. 원본 학습 데이터(BEAT, BEAT2)와 사람 몸 모델(SMPL-X)은 비상업이다. 다른 후보(StreamTalk, GestureLSM, MambaTalk, DiffSHEG, SynTalker 등)는 코드 라이선스는 허용적이지만 **가중치가 학습한 데이터와 몸 모델이 비상업이라 상업 가능을 뜻하지 않는다.** 일부는 학습 코드가 미공개이거나 학습 데이터 권리가 불명확하다.
- **형식:** 전부 사람 골격(SMPL-X·BVH) 출력이고 4초 이상 발화를 전제한다. 22관절 비인간 리그로 옮기는 코드는 없다(비인간 대상 Motion2Motion은 라이선스 없음).
- **품질:** GENEA 대회 전반에서 "어울림"이 약하다는 보고. 우리 시범에서도 자기 음성과의 동기 증거는 없었다([ANIMATION_AND_ACTING](../content/ANIMATION_AND_ACTING.md) 6절).
- **저작권 문의:** 상업 배포를 정하기 전에 저자에게 서면 확인이 필요하다. 문의문 초안을 만들었으나 **발송하지 않았다.** 회신 전에는 내부 평가까지만 한다.
- 우리 구조(고정 음성 클립 + 신호별 연기)에 맞는 방법: ⓐ 소리에서 타이밍(말 시작·강세·쉼·구 끝)을 뽑아 손으로 만든 동작 키를 정렬 ⓑ 대사 의미 태그로 사전 제작 클립 고르기 ⓒ 생성 모델은 오프라인 참고 영상용.

## 3. 3D 아바타 + 애니메이션 자산이 실제로 있는 저장소

GitHub 트리 API로 모델·모션 파일(`.glb .gltf .vrm .fbx .vrma .bvh .vmd`)을 세어 확인했다(파일 내용 미다운로드).

- **가장 가까운 것:** CC0 모션 팩 63클립(대기·듣기·의미 동작·말하는 중 루프·제스처 구절)과 헤드리스 Blender 제작 파이프라인(IK 리그, 변형 메시 충돌 검사, 속도 튐 계수, FK 측정), 런타임의 강세 음절 타격 스케줄러가 공개돼 있다. 코드는 Apache-2.0. 대상은 VRM 사람형이라 우리 22관절 리그로 옮기려면 재타깃과 FK 검수가 필요하다.
- 그 밖: 제스처를 코드로 만드는 MIT 라이브러리, 대사를 읽어 제스처를 고르는 분류기, LLM이 키프레임을 만들고 지시 추종을 검사하는 도구 — **같은 발상의 참고 구현**이다.
- **비인간 캐릭터 + 대화 제스처 세트는 찾지 못했다.** 비인간 예시는 클립이 걷기·달리기뿐인 모델과, 상태 루프 7 + 일회성 동작 6 + 얼굴 morph 3의 로봇 모델(크로스페이드 예제. 우리 구조와 모양이 같다) 정도다.
- **런타임 기술:** 사용 중인 Filament 1.75.1 `Animator`에 크로스페이드(`applyCrossFade`)가 이미 있어 새 라이브러리 없이 전환을 부드럽게 할 수 있을 것으로 본다(소스 확인, 미시험).
- **대사 단어 시각 추출(정렬) 도구:** WhisperX(BSD-2, 한국어 정렬 모델 지정), Montreal Forced Aligner(MIT), ctc-forced-aligner(BSD-2)는 허용적이다. 정렬 모델 가중치 라이선스는 미확인이라 시각만 뽑고 배포물에는 넣지 않는다. AGPL 도구는 피한다.
- **GLB 검사·재샘플:** glTF-Transform(MIT), glTF-Validator.
- 맞지 않는 것: 최신 툴체인을 요구하는 뷰어 라이브러리(우리 compileSdk/AGP/Kotlin보다 높음), 유료 데이터셋 기반 모델, 로봇 재타깃(개념만).

## 4. 외부 서비스 단서

Meshy 애니메이션 API(라이브러리 클립 다수, 액션당 크레딧)가 있으나 약관과 우리 리깅 작업 보유 여부는 확인하지 못했다. 번들된 Meshy 캐릭터 33종 중 스킨이 있는 30종은 24관절 이름이 같지만 **팔·어깨 기본 회전이 달라**, 한 캐릭터의 팔 자세 규격을 다른 캐릭터에 복사하면 안 된다. 캐릭터마다 FK와 3방향 메시 렌더로 다시 구한다.

## 5. 아직 모르는 것

- 한국어 정렬 모델의 가중치 라이선스, 연구 모델이 학습한 데이터의 현재 권리, 저자 답변
- 모든 후보의 실제 동작(설치·실행 안 함), 재타깃 코드가 우리 뼈 이름을 알아보는지
- 한국어 합성 음성에서의 동작 품질을 사람이 보고 들었을 때의 판단
