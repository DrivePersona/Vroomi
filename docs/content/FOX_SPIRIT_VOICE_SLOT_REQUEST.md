# 음성 팩 SDK 요청: 여우 신령 빠진 대사 슬롯 8개

**기준일:** 2026-11-14 · **대상:** `voice-pack-sdk`(비공개) `ai.fox-spirit.voicedesign` · **짝 캐릭터:** `ai.meshy.fox`(여우 신령, 화면에는 무녀 복장) · **요청한 쪽:** 앱(이 저장소) · **상태:** 요청. 대사 확정과 음성 생성은 비공개 저장소에서 한다.

## 1. 요약

여우 신령은 차량 신호 대사 13개 슬롯 중 **5개만 음성(WAV)이 있다.** 나머지 8개 슬롯은 음성이 없어 앱이 캐릭터 목소리 대신 차량 기본 TTS로 앱 기본 문구를 읽거나(대체 재생), 아무 말도 하지 않는다. 이 문서는 그 8개 슬롯의 **대사 확정**과 **음성 생성**을 요청한다.

- 캐릭터 목소리로 만들 슬롯 6개: `DOOR`, `WINDOW`, `AMBIENT_LIGHT`, `HVAC`, `WIPER`, `CHARGE`
- 중립 음성으로 만들 슬롯 2개: `WARNING`, `ENERGY_LOW`(안전 정책상 캐릭터 말투·몸짓 없음)
- 함께 확인할 것: 공개 초안 대사와 실제 클립 문구가 다르다(§4). 어느 쪽이 최종인지 정해 달라.

근거는 [FOX_UTTERANCE_CHECK](../evidence/FOX_UTTERANCE_CHECK.md)(AVD 실측)와 [RELEASE_VOICE_CHARACTER_PLAN](RELEASE_VOICE_CHARACTER_PLAN.md)(2026-11-05 커버리지 스냅샷)이다.

## 2. 지금 상태

"있음"은 [RELEASE_VOICE_CHARACTER_PLAN](RELEASE_VOICE_CHARACTER_PLAN.md)의 "기존 팩은 팩당 5개(인사·BRAKE·TURN·MODE·TIRE)" 기준이다. 팩 파일의 슬롯 목록을 직접 열어 확인하지는 않았다.

| 슬롯 | 앱에서 나오는 경우 | 음성 | AVD에서 들린 것(로그 기준) |
| --- | --- | --- | --- |
| GREETING | 앱 시작 | 있음 | 클립 재생됨(문구는 로그에 없음) |
| BRAKE | 브레이크 밟음 | 있음 | "오냐, 천천히 가거라." 클립 재생됨 |
| TURN | 방향지시등 켬 | 있음 | "깜빡이 켰구나. 좋도다." 클립 재생됨 |
| MODE | 주행 모드 바꿈 | 있음 | 콘솔에 신호가 없어 확인 못 함 |
| TIRE | 타이어 공기압 낮음 | 있음 | 플랫폼상 자동 신호가 없어 확인 못 함 |
| **DOOR** | 도어 열림·잠금·프렁크 | **없음** | 기본 TTS "도어 상태가 바뀌었어." |
| **WINDOW** | 창문 위치·잠금 | **없음** | 기본 TTS "창문 설정이 바뀌었어." |
| **AMBIENT_LIGHT** | 실내등·독서등·앰비언트 색 | **없음** | 기본 TTS "조명 설정이 바뀌었어." |
| **HVAC** | 공조 전원·온도·풍량·시트 열선 등 | **없음** | 기본 TTS "편의 설정이 바뀌었어." |
| **WIPER** | (앱 반응 없음, §7) | **없음** | 와이퍼 Auto가 HVAC 문구로 읽힘 |
| **CHARGE** | 충전구 열림 | **없음** | 발화 없음(데이터만 수신, §7) |
| **WARNING** | 안전벨트 미착용 경고 | **없음** | 콘솔이 신호를 줄 수 없어 확인 못 함 |
| **ENERGY_LOW** | 에너지 부족(긴급) | **없음** | 확인 못 함 |

"기본 TTS"는 차량 기본 음성 합성(Pleos TextToSpeech)이다. 여우 목소리가 아니고, 문구도 여우 대사가 아니라 앱 코드의 기본 문구(`VehicleEvent` 텍스트)다.

## 3. 요청 내용

### 3.1 캐릭터 목소리 슬롯 6개

여우 신령 목소리(VoiceDesign)로, 기존 BRAKE·TURN 클립과 같은 말투·길이로 만든다. 한 슬롯이 여러 신호(예: DOOR는 열림·닫힘·잠금)를 함께 받으므로 **방향을 말하지 않는 문구**여야 한다.

| 슬롯 | 공개 초안(DRAFT) | 제안 문구(기존 클립 말투, 미승인) | 정책 |
| --- | --- | --- | --- |
| DOOR | 도어 상태가 달라졌어요. | 문 상태가 바뀌었구나. | 정차 중만 |
| WINDOW | 창문 상태가 달라졌어요. | 창문이 움직였구나. | 정차 중만 |
| AMBIENT_LIGHT | 실내 조명이 조정됐어요. | 불빛이 바뀌었구나. | 정차 중만 |
| HVAC | 공조 설정이 바뀌었어요. | 바람과 온기를 바꾸었구나. | 정차 중만 |
| WIPER | 와이퍼 설정이 달라졌어요. | 와이퍼를 바꾸었구나. | 정책 승인 전까지 기본 무음 |
| CHARGE | 충전 상태가 바뀌었어요. | 충전구가 움직였구나. | 정차 중만, 상태 변화 확인 전까지 꺼 둠 |

제안 문구는 앱 쪽에서 기존 클립 두 개의 말투를 따라 쓴 초안이다. 최종 문구는 비공개 대사 매트릭스에서 정한다. 페르소나 규칙(초자연적 효능·운세·보호를 약속하지 않는다)은 지킨다.

### 3.2 중립 음성 슬롯 2개

안전 이벤트는 캐릭터 말투와 몸짓 없이 중립 음성으로만 말한다(앱 정책 `NEUTRAL_CLIP`). 여우 목소리로 만들지 않는다.

| 슬롯 | 공개 초안(DRAFT) | 지금 앱 기본 문구 |
| --- | --- | --- |
| WARNING | 차량 경고가 있어요. 내용을 확인해 주세요. | 차량 경고가 있어요. |
| ENERGY_LOW | 에너지 잔량이 낮아요. | 에너지가 부족합니다. 충전 또는 주유가 필요해요. |

둘 중 어느 문구로 녹음할지 정해 달라. 정한 문구에 맞춰 앱 기본 문구도 고친다(클립이 없을 때 같은 말이 나오도록).

### 3.3 함께 확인할 것

- **MODE·TIRE 클립:** 팩에 실제로 있는지, 문구가 무엇인지 알려 달라. 앱에서 신호를 넣을 수 없어 들어 보지 못했다.
- **GREETING 문구:** 로그에 문구가 남지 않아 확인하지 못했다. 매니페스트의 문구를 알려 달라.

## 4. 대사 기준이 두 개다

- 이 저장소의 [DIALOGUE_MATRIX.csv](DIALOGUE_MATRIX.csv)는 오래된 공개 초안(전부 DRAFT)이고, [RELEASE_VOICE_CHARACTER_PLAN](RELEASE_VOICE_CHARACTER_PLAN.md)에 따르면 비공개 음성 팩 매트릭스를 덮어쓰지 않는다.
- 공개 초안의 여우는 "고요하고 품위 있는 **존댓말**"인데, 실제 클립은 "오냐, 천천히 가거라." "깜빡이 켰구나. 좋도다."처럼 **고풍스러운 반말**이다.

요청: 여우의 말투를 어느 쪽으로 할지 정하고, 정한 쪽으로 13개 슬롯을 맞춰 달라. 반말로 정하면 공개 초안의 여우 행도 고친다(이 저장소에서 할 일).

## 5. 전달 형식

[RELEASE_ROSTER](RELEASE_ROSTER.md)의 런타임 검사와 같다.

- 슬롯마다 인덱스된 변형(variant)을 하나 이상. 문구(text)를 매니페스트에 함께 둔다.
- 비공개 SDK에 해시·크기·길이를 게시한다(SDK 테스트가 WAV 파싱·길이를 검사한다).
- 권리 메타데이터(`commercialUse`, 동의)는 이 요청으로 바꾸지 않는다. 근거 없이 `true`로 올리지 않는다.
- 같은 문제가 다른 기존 팩 9개에도 있다(팩당 8개). 이 요청은 여우만 다루지만, 같은 형식을 다른 팩에 그대로 쓸 수 있다.

## 6. 완료 확인 방법

새 팩을 앱에 넣은 뒤 [FOX_UTTERANCE_CHECK](../evidence/FOX_UTTERANCE_CHECK.md)와 같은 방법으로 다시 잰다.

- DOOR·WINDOW·AMBIENT_LIGHT·HVAC 신호에서 로그에 `대체 재생`이 없고 `재생됨`만 남는다.
- 대사가 확정 문구와 같다(로그의 `말하기 요청 "…"`).
- 정차 중에만 말하고, 주행(D) 중에는 `주행 중이라 차단`이 남는다.
- 에뮬레이터 확인은 실차 확인이 아니다. 소리를 귀로 확인하는 단계를 따로 둔다.

## 7. 앱 쪽에 남은 일 (이 요청과 별개)

- **WIPER:** 앱은 와이퍼 상태를 데이터로만 받고 반응 이벤트가 없다(`voicePackClipEventIds`에 슬롯만 있음). 지금 와이퍼 Auto가 말하는 것은 다른 구독 경로가 `COMFORT`(HVAC 슬롯)로 보내기 때문이다. 클립이 생기면 앱이 WIPER로 보낼지 정해야 한다.
- **CHARGE:** 충전구 열림은 이번 점검에서 데이터만 오고 이벤트가 없었다. 클립이 생겨도 앱 쪽 이벤트를 먼저 확인해야 한다.
- 앱 기본 문구를 §3.2에서 정한 중립 문구에 맞춘다.
