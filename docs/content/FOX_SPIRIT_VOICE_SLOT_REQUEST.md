# 음성 팩 SDK 요청: 여우 신령 빠진 대사 슬롯 8개

**기준일:** 2026-11-14 · **대상:** `voice-pack-sdk`(비공개) `ai.fox-spirit.voicedesign`(앱이 쓰는 `voicepack-content` 0.6.0 안의 팩 0.3.0) · **짝 캐릭터:** `ai.meshy.fox`(여우 신령, 화면에는 무녀 복장) · **요청한 쪽:** 앱(이 저장소) · **상태:** 여우 목소리 18개는 앱 쪽에서 생성해 에뮬레이터에서 재생까지 확인했다(§8). `voice-pack-sdk` 반영과 중립 2개는 남았다. 말투는 고풍스러운 반말로 정했다. 문구 목록은 [FOX_SPIRIT_VOICE_SLOTS.csv](FOX_SPIRIT_VOICE_SLOTS.csv)다.

## 1. 요약

여우 신령은 차량 신호 대사 13개 슬롯 중 **5개만 음성(WAV)이 있다.** 나머지 8개 슬롯은 음성이 없어 앱이 캐릭터 목소리 대신 차량 기본 TTS로 앱 기본 문구를 읽거나(대체 재생), 아무 말도 하지 않는다. 이 문서는 그 8개 슬롯의 음성 생성을 요청한다.

- 여우 목소리로 만들 슬롯 6개 × 변형 3개 = **18개**: `DOOR`, `WINDOW`, `AMBIENT_LIGHT`, `HVAC`, `WIPER`, `CHARGE`
- 중립 음성으로 만들 슬롯 2개 = **2개**: `WARNING`, `ENERGY_LOW`(안전 정책상 캐릭터 말투·몸짓 없음, 모든 캐릭터 공통 문구)
- 말투: 이미 있는 클립과 같은 **고풍스러운 반말**(…느니라·…도다·…거라·…구나)로 정했다(2026-11-14).

근거는 [FOX_UTTERANCE_CHECK](../evidence/FOX_UTTERANCE_CHECK.md)(AVD 실측)와 앱이 쓰는 팩 파일(아래 §2)이다.

## 2. 지금 있는 음성 (팩 파일로 확인)

`voicepack-content` 0.6.0의 `assets/voicepacks/ai.fox-spirit.voicedesign/manifest.json`을 열어 확인했다. 슬롯마다 변형 3개, 인사 1개로 클립이 13개 있다.

| 슬롯 | 클립 문구 | AVD에서 들린 것(로그 기준) |
| --- | --- | --- |
| GREETING | 여우 신령, 곁에 있느니라. | 재생됨 |
| BRAKE | 오냐, 천천히 가거라. / 감속을 확인했느니라. / 천천히 가거라. 안전하도다. | 첫 변형 재생됨 |
| TURN | 깜빡이 켰구나. 좋도다. / 방향 신호를 보았도다. / 방향 전환, 잘 되었느니라. | 첫 변형 재생됨 |
| MODE | 모드 변경. 좋도다. / 주행 모드가 바뀌었도다. / 선택한 모드로 가거라. | 콘솔에 신호가 없어 확인 못 함 |
| TIRE | 타이어 살피거라. / 타이어 상태를 살피거라. / 안전한 곳에서 점검하거라. | 자동 신호가 없어 확인 못 함 |

팩 메타데이터: 생성 방식 `VoiceDesign 1.7B reference -> Base 1.7B voice clone`(Qwen3-TTS), 상태 "청취·음색 차이 검증용 시제품", 대사 기준 `docs/RELEASE_DIALOGUE_MATRIX_V1.json`(비공개).

## 3. 요청 내용

슬롯별 문구 전체(변형 포함)는 [FOX_SPIRIT_VOICE_SLOTS.csv](FOX_SPIRIT_VOICE_SLOTS.csv)의 `status = TO_GENERATE` 행이다. 파일 이름은 기존 클립 규칙(`<slot>.wav`, `<slot>-2.wav`, `<slot>-3.wav`)을 따랐다.

### 3.1 여우 목소리 슬롯 6개

기존 클립과 같은 음성(같은 VoiceDesign 참조와 클론)으로 만든다. 한 슬롯이 여러 신호(예: DOOR는 열림·닫힘·잠금)를 함께 받으므로 **방향을 말하지 않는 문구**로 썼다.

| 슬롯 | 변형 1 | 변형 2 | 변형 3 | 정책 |
| --- | --- | --- | --- | --- |
| DOOR | 문 상태가 바뀌었구나. | 문의 기척이 달라졌도다. | 문이 움직였느니라. | 정차 중만 |
| WINDOW | 창문이 움직였구나. | 창의 상태가 바뀌었도다. | 창문을 살폈느니라. | 정차 중만 |
| AMBIENT_LIGHT | 불빛이 바뀌었구나. | 실내 등불이 달라졌도다. | 조명이 바뀌었느니라. | 정차 중만 |
| HVAC | 바람과 온기를 바꾸었구나. | 공조가 달라졌도다. | 실내 온기를 맞추었느니라. | 정차 중만 |
| WIPER | 와이퍼를 바꾸었구나. | 와이퍼가 달라졌도다. | 앞 유리를 살피거라. | 정책 승인 전까지 기본 무음 |
| CHARGE | 충전구가 움직였구나. | 충전 상태가 바뀌었도다. | 충전을 살폈느니라. | 정차 중만, 상태 변화 확인 전까지 꺼 둠 |

문구는 앱 쪽에서 기존 클립 말투를 따라 쓴 초안(DRAFT)이다. 비공개 대사 매트릭스에서 확정(TEXT_APPROVED)한 뒤 생성한다. 페르소나 규칙(초자연적 효능·운세·보호를 약속하지 않는다)과 공개 매트릭스 검사(숫자·"보장" 같은 단정 금지)를 지켰다.

### 3.2 중립 음성 슬롯 2개

안전 이벤트는 캐릭터 말투와 몸짓 없이 중립 음성으로만 말한다(앱 정책 `NEUTRAL_CLIP`). 여우 목소리로 만들지 않는다. 문구는 [DIALOGUE_MATRIX.csv](DIALOGUE_MATRIX.csv)에서 모든 캐릭터가 함께 쓰는 문장이다.

| 슬롯 | 녹음할 문구 | 지금 앱 기본 문구(클립이 없을 때) |
| --- | --- | --- |
| WARNING | 차량 경고가 있어요. 내용을 확인해 주세요. | 차량 경고가 있어요. |
| ENERGY_LOW | 에너지 잔량이 낮아요. | 에너지가 부족합니다. 충전 또는 주유가 필요해요. |

앱 기본 문구와 공통 문장이 다르다. 앱 기본 문구는 모든 캐릭터에 걸린 문구라 이 요청과 별도로 맞춘다(§7).

## 4. 말투 결정 (2026-11-14)

- 공개 초안의 여우는 "고요하고 품위 있는 존댓말"이었고 실제 클립은 고풍스러운 반말이었다. **반말로 정했다.**
- 공개 초안 [DIALOGUE_MATRIX.csv](DIALOGUE_MATRIX.csv)의 여우 13개 행을 이 결정에 맞췄다. 페르소나를 반말로 바꾸고, 클립이 있는 5개 슬롯은 실제 클립의 첫 변형 문구로(상태 `AUDIO_GENERATED`), 새 6개 슬롯은 §3.1의 변형 1로(상태 `DRAFT`) 바꿨다. 중립 2개는 공통 문장 그대로 둔다.
- 공개 초안은 비공개 매트릭스를 덮어쓰지 않는다([RELEASE_VOICE_CHARACTER_PLAN](RELEASE_VOICE_CHARACTER_PLAN.md)). 비공개 매트릭스에도 같은 결정을 반영해 달라.

## 5. 전달 형식

[RELEASE_ROSTER](RELEASE_ROSTER.md)의 런타임 검사와 같다.

- 슬롯마다 인덱스된 변형을 하나 이상(기존 슬롯처럼 3개를 권한다). 문구(text)를 매니페스트에 함께 둔다.
- 오디오 형식은 기존 클립과 같게: `wav-pcm16`, 24000Hz, 모노.
- 비공개 SDK에 해시·크기·길이를 게시한다(SDK 테스트가 WAV 파싱·길이를 검사한다).
- 권리 메타데이터(`commercialUse`, 동의)는 이 요청으로 바꾸지 않는다.
- 같은 공백이 다른 기존 팩 9개에도 있다(팩당 8개 슬롯). 이 요청은 여우만 다루지만, 같은 형식을 다른 팩에 그대로 쓸 수 있다.

## 6. 완료 확인 방법

새 팩을 앱에 넣은 뒤 [FOX_UTTERANCE_CHECK](../evidence/FOX_UTTERANCE_CHECK.md)와 같은 방법으로 다시 잰다.

- DOOR·WINDOW·AMBIENT_LIGHT·HVAC 신호에서 로그에 `대체 재생`이 없고 `재생됨`만 남는다.
- 대사가 목록 문구와 같다(로그의 `말하기 요청 "…"`).
- 정차 중에만 말하고, 주행(D) 중에는 `주행 중이라 차단`이 남는다.
- 에뮬레이터 확인은 실차 확인이 아니다. 소리를 귀로 확인하는 단계를 따로 둔다.

## 7. 앱 쪽에 남은 일 (이 요청과 별개)

- **WIPER:** 앱은 와이퍼 상태를 데이터로만 받고 반응 이벤트가 없다(`voicePackClipEventIds`에 슬롯만 있음). 지금 와이퍼 Auto가 말하는 것은 다른 구독 경로가 `COMFORT`(HVAC 슬롯)로 보내기 때문이다. 클립이 생기면 앱이 WIPER로 보낼지 정해야 한다.
- **CHARGE:** 충전구 열림은 이번 점검에서 데이터만 오고 이벤트가 없었다. 클립이 생겨도 앱 쪽 이벤트를 먼저 확인해야 한다.
- **중립 기본 문구:** 앱 기본 문구(`VehicleEvent.WARNING`, `ENERGY_URGENT`)를 §3.2의 공통 문장에 맞출지 정한다. 웹 시뮬레이터(`engine.js`)와 테스트도 같은 문구를 쓴다.

## 8. 앱 쪽 생성 결과 (2026-11-14)

`voice-pack-sdk`에 접근할 수 없어, 여우 목소리 18개를 앱 쪽에서 먼저 만들어 시험했다. 생성한 WAV는 공개 저장소에 넣지 않는다(이 저장소는 계약·절차·증적만 둔다).

| 항목 | 내용 |
| --- | --- |
| 모델 | `Qwen/Qwen3-TTS-12Hz-1.7B-Base`(Apache-2.0), 패키지 `qwen-tts` 0.1.1, Apple M4(MPS) |
| 참조 음성 | 기존 여우 클립 4개(인사·BRAKE·TURN·TIRE 첫 변형)를 0.3초 쉼으로 이어 붙인 약 10초와 그 문구 |
| 후처리 | 기존 클립에 맞춤: 24kHz·모노·PCM16, 앞 무음 0.08초·끝 무음 0.34초, 최대 진폭 0.71, 끝 10ms 페이드 |
| 결과 | 18개, 길이 1.66~2.17초. 목록의 `status = GENERATED_LOCAL` 행 |
| 청취 | 사용자가 청취 페이지로 듣고 "괜찮다"고 했다(2026-11-14). 공개 매트릭스 상태는 `AUDIO_GENERATED`로 올렸다 |
| 앱 확인 | 팩 버전 `0.3.1-local`로 묶어 `internalDebug`의 내부 자산(git 무시 경로)에 넣고 AVD에서 재측정했다. 공조·도어·창문·조명 신호가 `대체 재생` 없이 여우 클립으로 `재생됨`([FOX_UTTERANCE_CHECK](../evidence/FOX_UTTERANCE_CHECK.md)) |

남은 것:
- **`voice-pack-sdk` 반영:** 18개 WAV와 매니페스트 추가분(문구·크기·sha256)을 비공개 팩에 넣고 `voicepack-content`를 새로 게시해야 앱 기본 빌드에 들어간다. 지금 앱 기본 빌드(0.6.0)에는 없다.
- **중립 2개(WARNING·ENERGY_LOW):** 어느 팩에도 중립 참조 음성이 없어 만들지 않았다. 모든 캐릭터가 함께 쓰는 음성이라 따로 정한다.
- **`gestureId`:** 새 슬롯 클립에는 비워 뒀다. 캐릭터 매니페스트의 지원 몸짓을 확인한 뒤 채운다.
- **권리 메타데이터:** 바꾸지 않았다. 시제품 메모만 매니페스트 `prototype.localAdditions`에 남겼다.
