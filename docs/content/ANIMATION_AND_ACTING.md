# 캐릭터 연기와 애니메이션: 방법과 교훈

**기준일:** 2026-11-12 · 첫 시험 캐릭터(여우 신령)에서 얻은 결과. 캐릭터 에셋과 클립 GLB는 비공개 `character-pack-sdk`에 있고, 이 문서는 **방법·측정·교훈·구조 설계**만 담는다.

## 1. 목표

신호마다 포즈 하나를 붙이는 것이 아니다. 신호의 뜻을 캐릭터가 알아차리고, 자기 성격대로 반응하고, 안정된 상태로 돌아오는 연기를 만든다. 동작 수보다 **인지·감정·타이밍·시선·후속 움직임의 일관성**이 우선이다.

비트 구조: 알아차림 → 준비 → 핵심 반응 → 잔동작 → 회복(idle 복귀). 음성이 시작되는 시점과 맞물려야 한다.

신호는 먼저 분류한다.

| 종류 | 예 | 다루는 법 |
| --- | --- | --- |
| 에지 이벤트 | 브레이크 눌림 | 한 번의 반응 |
| 이산 상태 전환 | 방향지시등, 드라이브 모드 | 전환마다 반응 |
| 지속·연속 값 | 밝기, 배터리 잔량 | 매 표본마다 몸짓으로 바꾸지 않고, 확인된 임계 전환이나 시각 파라미터로 |
| 안전 경고 | 차량 경고, 안전벨트 | **몸짓 없음, 중립 음성** |
| 주행 게이트 | 기어 D | 오버레이 숨김 |
| 미지원·미검증 | 타이어 등 | 자동 반응에 연결하지 않음 |

## 2. 제작 흐름

| 단계 | 산출물 | 비고 |
| --- | --- | --- |
| 연기 명세 | 신호별 비트·타이밍·금지 동작·리그 한계를 적은 문서 | 먼저 사용자에게 보여 주고 승인받은 뒤 만든다 |
| 구조화 명세 | 채널별 키프레임 JSON (PCHIP 곡선) | 빌더가 GLB로 굽는다 |
| 빌더 | 규격 JSON → GLB 애니메이션 클립, 재빌드 시 바이트 동일 | 결정적 |
| 검수기 | 숫자 기준으로 GLB를 다시 재어 합격 판정 | 아래 3절 |
| 눈·귀 판정 | 사람이 메시 렌더·소리와 함께 확인 | 검수기가 못 보는 귀여움·자연스러움 |

음성·애니메이션 생성은 코딩 에이전트에 맡기고, 프롬프트 작성과 검증은 별도 패스에서 사람이 한다. 구현과 검증을 같은 패스에서 하지 않는다.

## 3. 검수기 설계 교훈

1. **명세 준수와 "실제로 그렇게 움직이는가"는 다르다.** 검수기 PASS는 "GLB가 JSON 명세와 같다"만 보증한다. GLB를 FK(순방향 운동학)로 직접 계산해 몸 기준 좌표로 재는 별도 측정이 필요하다. 첫 측정은 97항목 중 95개가 통과했고 2건은 어깨가 몸보다 늦게 내려앉는 타이밍 미달이었다.
2. **클립끼리 구분되는지를 재야 한다.** 이전 검수기는 클립마다 자기 명세만 봐서 방향지시등≈드라이브 모드, 브레이크≈타이어처럼 비슷한 동작이 통과했다. 클립마다 **서명 지표**(예: 머리 돌림 각도, 두 손 사이 거리, 상체 숙임)를 정하고 "다른 클립은 이 값 아래/위"를 기준으로 넣었다.
3. **"고장난 동작"의 알려진 원인을 직접 잡는다:** 키마다 속도가 0이 되는 보간(움직이다 멈춤), 한 프레임에 꺾이는 관절(프레임당 9° 한도), 모든 채널이 한 시점에 동시에 정점, 말하는 동안 정지, 기본 자세 방치. 속도 기반 멈춤 검사는 다른 채널이 움직이면 가려지므로 키 수준 검사를 함께 둔다.
4. **검수기도 양방향으로 확인한다.** 정답 키는 통과, 일부러 깨뜨린 변이(머리 안 돌림, 팔 안 씀, 계단식, 뚝 꺾임, 서로 겹침, 낡은 GLB 등)는 걸리는지 본다. 19종 변이가 모두 걸렸다.
5. 호흡 꼬리(반응 종료 뒤)는 움직임 판정에서 뺀다. 머리 갸웃·어깨 높이 같은 값은 몸통 기울기가 섞이므로 몸통 대비 상대값으로 판정한다.
6. 팔을 크게 올리는 동작은 관절이 150~170° 돌아서, 한 프레임 한도를 지키려면 1.0초 안팎이 필요하다. **시간표를 짜기 전에 팔 자세별 관절 회전량으로 최소 이동 시간을 먼저 계산한다.**

## 4. 결과와 진단

- v0 → v2 → v3 순으로 갈아엎었다. 사용자는 "고장난 동작처럼 느껴지고 귀여운 느낌이 없다", "방향지시등과 드라이브 모드가 같아 보인다"고 지적했다.
- 진단 결론: **요청 방식의 문제가 아니라, 명세가 만든 문제 + 명세로는 못 고치는 시스템 문제의 합이다.**
  - 명세가 만든 것: 몸짓을 대사가 아니라 신호만 보고 설계(브레이크 몸짓은 '깜짝 놀람'인데 대사는 차분한 승낙), 대사 길이·쉼과 무관한 타이밍(12줄 중 6줄은 말하는 시간의 25% 이상을 몸이 정지한 채 말함), 귀여움 동작 어휘 부재, 기본 자세 방치.
  - 시스템 한계: 리그에 얼굴·귀·꼬리·손가락 관절과 모프 타깃이 없다(움직이는 관절 22개). 앱은 신호당 클립 1개만 고른다.
- v2: 기본 자세를 팔이 앞으로 뻗은 상태에서 몸 옆으로 내린 자세로 바꾸고, idle을 호흡·체중 이동·눈길이 있는 4.8초 반복으로 바꿨다. 브레이크는 대사 3줄에 맞춘 전용 클립 3개.
- v3: 동작 9종(브레이크·방향지시등·드라이브 모드·타이어·상향등·크루즈·실내등·문 열림·인사)을 서로 다른 **실루엣**으로 재설계. 총 12클립. 구분 수치 예: 방향지시등 머리 돌림 60.6°(다른 클립 ≤15°), 드라이브 모드 두 손 사이 95.7cm(≤47cm).
- **아직 사람 눈 판정 전이다.** 앱(Filament) 화면의 모습과 클립 반복 동작, 팔·소매가 몸에 파묻히는지(메시 충돌 검사 없음)도 미확인이다.

## 5. 줄별 몸짓 구조 설계 (설계 완료, 미구현)

**병목:** 대사 줄을 고르는 곳(클립 팩의 비공개 순환)과 몸짓을 고르는 곳(런타임)이 서로 모른다. 그래서 대사 12줄이 몸짓 4개를 나눠 쓰고(3:1), 이미 만든 클립 중 앱이 부를 수 있는 것은 12개 중 5개뿐이다. 전환도 기본 상태로 초기화한 뒤 인덱스만 바꾸는 방식이라 크로스페이드가 없다. 이 병목은 "제한 규칙" 때문이 아니라 **구현 구조** 때문이다.

바꿀 것:

| 단계 | 내용 |
| --- | --- |
| 5a 줄 통로 | 줄 순환의 소유를 선택기로 옮겨 `variantIndex`로 전달하고, 어느 줄이 말해졌는지 런타임에 알린다. 음성 계약은 불변 |
| 5b 줄 → 몸짓 | 캐릭터 manifest의 선택 필드로 줄별 클립 목록을 두고, 짝 음성 팩이 실제로 말했을 때만 줄 몸짓을 쓴다. 아니면 기본 몸짓 |
| 5c 크로스페이드 | Filament `Animator`의 크로스페이드를 직접 호출(자동 재생 끔). 반응 클립은 끝 자세를 유지(엔진이 시간을 감싸 반복시키므로) |
| 5d 콘텐츠 | 나머지 신호의 줄별 클립 제작 (저작 또는 생성) |

**구동 관절 닫힘 규칙:** `idle`은 모든 반응 클립이 움직이는 관절을 포함해야 한다. 크로스페이드는 양쪽 클립의 합집합 관절만 섞으므로, 반응 클립만 쓰는 관절은 이전 값이 남는다.

엔진·`Platform`·웹 시뮬레이터는 바뀌지 않는다. 현재 구현은 음성 재생 시작 후 캐릭터 manifest의 이벤트 기본 몸짓만 쓴다. **음성 클립별 몸짓은 미구현이며, 구현했다고 서술하지 않는다.**

## 6. 몸짓 생성 모델을 쓸 수 있나

음성에서 전신 동작을 만드는 연구 모델(EMAGE 계열)을 시범 적용했다. 요약: 같은 문제 영역이지만 **바로 쓸 부품이 아니다.**

- 22개 몸통 관절이 우리 리그와 1:1로 대응하고 CPU에서도 돈다(2초 분량 몇 초). 그러나 시작·끝 자세가 제각각이고 일부 구간에서 프레임당 변화가 한도를 넘는다.
- 한국어 합성 음성에서 **"말에 맞춘" 동기의 증거가 없었다**(모션 세기가 자기 음성을 다른 줄의 음성보다 더 잘 따르지 않음).
- 라이선스가 불명확하다(저장소에 LICENSE 없음, 학습 데이터·몸 모델은 비상업).
- 따라서 메인 연기 엔진이 아니라 **빌드 시점 리듬 생성기** 후보로만 둔다. 상세는 [RESEARCH_NOTES](../log/RESEARCH_NOTES.md).

## 7. 에이전트 협업에서 얻은 교훈

- 코딩 에이전트를 직접 호출했을 때 성공한 경우(표본 3회)의 공통점: 편집 범위가 JSON 채널 몇 개로 좁았고, 합격 기준이 숫자이며 실패 출력에 잰 값이 나왔고, **바뀌면 안 되는 부분을 해시로 잠갔고**, 작업을 3+5개처럼 작게 나눴다. 실패한 경우는 큰 다단계 편집을 한 번에 맡겼을 때다.
- 에이전트에게 파일 수정을 맡기기 전에 대상 폴더를 백업한다. git으로 관리되지 않는 작업 폴더는 수정을 되돌릴 수 없다.
- 낮은 추론 강도(`low`)로는 도구를 한 번도 쓰지 않고 틀린 답을 낸 적이 있어 쓰지 않는다.
- 미리보기 서버를 에이전트가 직접 띄우면 포트가 겹친다. 포트를 따로 정하거나 기존 서버를 쓰게 한다.
